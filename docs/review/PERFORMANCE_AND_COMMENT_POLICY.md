# Python Code to C Alpha1.0 — 性能・コメント方針

## 安全に適用した最適化

| 対象 | 変更 | 効果 | 互換性上の扱い |
|---|---|---|---|
| 小整数 | `-5` から `256` の整数を静的キャッシュ化 | 数値リテラル、添字、range、長さ計算でのヒープ確保とGC追跡を削減 | キャッシュはGC追跡リストに入らず、値と通常の整数演算APIは維持 |
| リストリテラル | `p2c_list_from_array()` を逐次appendから一括確保・コピーへ変更 | 既知要素数のリスト生成における再確保と容量倍増を削減 | 既存のリスト容量・要素順・ランタイムAPIを維持 |
| メソッド呼び出し | デフォルト引数をアダプタで補完 | 呼び出し側の特殊分岐を不要にし、Pythonの通常のメソッド呼び出しに近づける | 必須・過剰引数は明確なTypeErrorとして処理 |

## 最適化しない領域

GCを参照カウントのみへ置き換える、例外処理を省略する、境界チェックを削除する、ユーザーオブジェクトの文字列を無条件で共有する、といった変更はメモリ安全性またはPython意味論を壊しやすいため採用しません。性能向上は、静的キャッシュ、既知長の一括確保、重複登録除去、バッファ再利用のように意味論を変えない範囲に限定します。

## 計測方法

短時間の変換ではOSの時刻分解能に収まるため、単発のミリ秒値を性能結論に使いません。性能変更は、`tests/complex_alpha10.py` の変換、生成Cの実行、`make test`、`make freestanding` を反復し、機能結果、生成Cのサイズ、ヒープ確保回数を比較して評価します。目標は、数値・コンテナを多用する生成コードの不要な確保回数を減らしつつ、GC・例外・自作OSの固定アロケータで同じ結果を保つことです。

## ソースコメント方針

ソースコードには、外部契約、未定義動作の回避、所有権、GCルート寿命、プラットフォーム境界のように実装を読むだけでは判別できない情報だけを残します。機能一覧、設計上の背景、対応・未対応構文、移植手順、性能上の判断、テスト範囲は `docs/spec/` と `docs/build/` に記載します。新規実装では長い経緯説明をコード内へ追加しません。
